# HIF 饮料面板

「特製ハツボシエキス」新增「关联卡牌」，可选择多张 A 卡。原出牌策略选中任一候选时，先使用一瓶，再重新定位并打出原目标，不改变候选优先级。同名多瓶留给后续出牌；进行卡牌组合衔接时保留这瓶饮料。关联按职业保存在饮料条目的 `before_card_targets`，关联期间暂停普通定时用饮，清除后恢复原时机。不存在或禁用饮料不影响正常出牌；已用饮但无法确认目标或出牌结果时停止任务。

Maa「HIF培育」中的「HIF饮料配置」打开原生面板，默认显示主界面选择的职业。每个职业可从 28 种 P 饮料中按名称、稀有度和计划筛选导入；已导入饮料可删除、上移、下移。列表从上到下表示领取优先级。每行的「购买」默认不勾选；相谈和技能卡定制后的商店只购买已勾选的饮料，仍需开启对应的购买任务开关。「不使用」会排除该饮料的领取、购买和本战自动使用。每项使用时机可选“未指定”“每场第 1 回合”“剩余回合 = N”；「初星黒酢」另有“只在组合技使用”。

配置保存在 `config/hif/hif_drink_profiles.json`，各职业的数组顺序就是优先级。`purchase_enabled: true` 表示允许购买，`disabled: true` 表示不使用。领取页读完三个候选，再选择名单顺序最高且未禁用的饮料；没有名单命中时选首个可确认未禁用的候选。若三瓶都不可确认可领，则尝试拒领，不盲选禁用饮料。相谈商店比较下排四格，技能卡定制后的商店比较右下两格；按名单选择已勾选饮料，不读取格位价格。是否能买以游戏交换确认弹窗为准；未出现确认弹窗时停止购买。技能卡定制后的商店在余额不足 50 P 时停止。旧的固定目标饮料名单已移除。

商店逐格点击后先确认该格出现橙色选中边框，再只 OCR 详情名称；效果文字不参与饮料身份判断。已兑换格若点击后未被选中，不沿用上一格详情名称。边框检测已用 2026-09-27 的商店截图离线核对；相谈及定制后商店的完整点击结果仍需 MuMu 验证。

`default_use_timing_profiles` 为每个职业保存“未指定饮料使用时机”，覆盖未导入的饮料，以及已导入但单项 `use_timing` 未指定的饮料；默认剩余 4 回合，可设为每场第 1 回合、剩余回合 = N 或不自动使用。已设单项时机的饮料优先采用单项设置。本战按饮料栏从左到右展开详情，名称严格匹配且符合当前时机时，直接在当前详情中使用；未知、禁用或未到期的饮料取消后检查下一瓶。面板名单顺序用于领取和购买，不决定同回合的使用顺序。使用一瓶并确认补位后，从当前第一瓶继续检查，同名多瓶依次使用；不保存跨时机名称缓存。使用饮料进入选卡界面时，当前批次等待选卡处理完成和战斗页连续稳定出现，再校验数量恰好少一瓶，并继续同回合剩余的到期饮料；选卡页不参与瓶数校验，选卡失败或返回超时则停止本批次。

「初星黒酢」的“只在组合技使用”保存为 `use_timing: {"mode": "combo_only"}`，只对 ID 22 有效。选择后普通回合和开场时机都不会使用它，包括组合技完成或失败之后；仅允许开启「使用初星黒酢」的卡牌组合在寻找后续卡时使用。若勾选「不使用」，组合技也不使用它。未选择此模式时，仍可能用醋的组合优先保留；组合完成且不再等待之后按原有时机处理。缺少该模式的旧配置保留原行为，不自动更改已保存的职业名单或时机。旧普通饮料、全力茶及センブリソーダ专用触发路径暂留源码，不参与本战调度。**领取页满4瓶时按面板目标名单进行普通饮料栏舍弃；单种饮料数量上限仍未启用。**

目录 `config/hif_drink_catalog.json` 固定 [Gakumas Tools 饮料数据](https://github.com/surisuririsu/gakumas-tools/blob/9ff4610011feb395e363d86d7c961e4da68b6deb/packages/gakumas-data/json/p_drinks.json) 的 ID、名称、稀有度、计划与效果表达式，配套图标取自 [gk-img](https://github.com/surisuririsu/gk-img/tree/ac065b770d3d79bd8f01e179a88f613fcfbf24ae/docs/p_drinks/icons)，本地保存在 `resource/base/image/hif_drink_icons/<id>.webp`。目录记录逐图 SHA-256，`tests/test_hif_drink_catalog.py` 校验对应关系。效果表达式目前作为原始资料保存，未转换为游戏内说明。展示图不直接作为游戏画面识别模板。

本战逐瓶展开详情，先通过底部「使う／キャンセル」按钮确认弹窗稳定打开，再在 `[20,560,680,430]` 广域 OCR 中定位左侧「Pドリンク」，从标题下方 50～110 像素的名称行与目录做完整名称匹配。「詳細」被拆为独立 OCR 框或读成「7詳細」不影响名称定位；读到到期且允许使用的饮料后，直接点击当前详情中的「使う」，不先取消再重新打开复核。日志会区分已导入、未导入、不使用和无法识别；无法确认身份的饮料不使用。领取满栏舍弃流程已用 2026-10-09 的四张连续截图做原生 OCR 离线重放，完整自动点击仍需实机回归。领取、购买和本战使用的实际结果由用户在 MuMu 验证。

使用运行包自带的 Maa OCR 模型对现有 5 张本战详情、2 张相同布局的非战斗详情做离线复核：上述广域读取与目录严格匹配在 7/7 张截图中得到正确名称。尚无センブリソーダ、厳選初星チャイ的本战详情截图，需在 MuMu 日志中确认这两种饮料的识别情况。

领取与购买接入前，用运行包自带 Maa OCR 模型离线读取已有截图：`193801`～`193803` 的三种领取候选名称均读出；`194037`、`194038`、`194755` 的商店详情名称均读出。商店名称框收窄至 `[190,170,470,50]`，避免拼入下一行效果；领取名称取名称行文字框，避免拼入旁边的小符号。旧版曾从 `194037` 的特价栏读出 `P 75 52`；当前购买流程已不读取单瓶价格。以上仅验证静态画面的 OCR，不代表已验证游戏内点击与交换完成。

## 剩余回合识别复核

本战用饮仍按剩余回合精确相等触发。常规 OCR 没有读出数字时，对同一帧的 `[34,68,56,44]` 数字区再做一次 `only_rec` 整区直接识别，要求完整的 1～99 数字和至少 0.9 置信度；随后仍检查相邻回合变化，并保留 1/7 的笔画复核。备用识别失败时不沿用上次回合，不将 `X` 固定替换为 4，也不在错过目标回合后补喝。日志中的 `HIF剩余回合OCR复核` 表示备用识别得到了数字。

此路径已用已有 MuMu 录像的 64 帧剩余 4 回合画面离线验证，整区直接识别均正确得到 4；该录像不是 2026-10-07 这次漏用的画面，修复后的实际用饮仍需 MuMu 回归。

## 领取满栏时舍弃饮料

此流程针对可以点开下方手持饮料、点击「捨てる」的普通领取页。先识别待领取三瓶，确认有当前职业的面板目标且手持已满4瓶，才逐瓶读取手持名称。优先保留名单目标，从非目标里舍弃最低优先级的一瓶（不在名单中的优先级最低；同级取最右侧，禁用饮料优先舍弃）。四瓶全为目标或待领取没有目标时拒领，不舍弃目标饮料。

详情名称、操作按钮位置连续三帧稳定后才操作。逐瓶读取后点击「キャンセル」，确认详情标题消失且领取页连续稳定，再检查下一瓶；按钮仍在移动时不点击。舍弃前复核同一饮料名称及「捨てる」，随后核对同名废弃问题及按钮位置，稳定后点击「はい」。同一确认窗仍在时最多点击两次；仍未生效则点「いいえ」并关闭详情，确认原有4瓶未减少后拒领本次饮料，继续任务。结果无法确认时明确返回任务失败，不让异常越过 Agent 回调。

连续确认手持4→3瓶及返回领取页后，重新点选原待领取目标，复核名称再领取。读取不到手持身份时保留现有饮料。领取只按职业饮料面板决定，不再读取旧「默认不拿」开关或配置字段。此逻辑不改动勾选待领取／手持条目后点「残す」的另一种上限页面。

## 勾选式所持上限页

两套 HIF 任务均提供「所持上限页按优先级保留」，每个任务独立保存，默认关闭。关闭时保留全部已有选择，只补缺位：先补未选中的手持饮料，没有手持候选时继续检查收到的饮料，按页面顺序补选。此模式不读取优先级，也不打开名称详情。

开启时完整扫描收到与手持饮料，再按当前职业名单重选：启用的名单项优先，名单外其次，禁用项最后；同级优先手持。同款多瓶独立计数，隐藏条目通过短距离滚动读取，容量由完整清单的已选数与剩余数核对，不固定为4。图标有歧义时点击信息按钮，读取「Pドリンク詳細」标题下方、图标右侧的名称，确认关闭并返回列表后才检查下一瓶。

橙色复选框与黄色背景表示选中，灰色框里的白勾表示未选。每次只调整一瓶，同时核对勾选状态与剩余数变化；点击后的短暂过渡帧继续等待，不重复切换。身份不明时使用基础补选；若重选已开始但失败，先恢复初始选择。只有选择数为0、按钮可用、上限页及画面连续三帧稳定，且保留集合一致时，才点击「残す」。无法确认分组、计数或恢复时停止，并在日志说明原因。此开关不影响普通领取页的舍弃流程。

保留了新饮料时，提交后还会显示领取动画。名称前的饮料图标若被 OCR 合并成一两个字符，仍可通过完整目录名称的唯一后缀确认动画；不模糊匹配名称或效果文案。普通领取页的「受け取るPドリンクを選んでください」提示及底部「受け取る」按钮优先于饮料名称判定，避免把瓶身上的「初星水」当成领取动画；提示出现但按钮尚未稳定时只等待。连续识别到动画后逐次点击左上角跳过，每步重新截图确认，最多12次，并限制等待时间。效果文字中的「レッスン」不再当作下一页面；只在动画结束、可操作页面稳定后返回入口。若动画后又出现第二个上限页，确认上一弹窗确已退出后交回 HIF 入口，创建新的扫描和提交事务，不沿用上一轮的选择记录。

「残す」点击后至少等待1.5秒。上限页仍在时比较画面：内容已变化则交回入口重新处理当前页；未明显变化、无法区分原页／第二页时重新扫描，并重新执行当前模式的规则，再决定补点，不会仅因无法区分而结束任务。新页有缺位时先补齐；优先级模式重新比较当前候选。上次点击在重扫或补点前延迟生效时，立即停止补点，转入领取动画或下一页面。一次动作累计最多6次点击「残す」（首次＋最多5次补点）；仍无可确认推进，或已经离开上限页但无法识别下一页面时，才报错停止，避免无限点击。
