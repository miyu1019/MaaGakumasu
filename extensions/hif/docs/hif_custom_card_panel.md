# HIF 技能卡定制面板

「HIF培育」中显示的「HIF技能卡定制配置」是唯一前台入口，对应游戏日文「スキルカードカスタマイズ」。内部任务键仍为 `HIF自定义卡配置`，以保持已有任务配置可读。旧的逐卡任务选项不再显示，也不会迁移；已有面板选择仍保留。点击「导入卡牌」可按卡名、稀有度、计划、分类、来源、导入状态及定制项数组合筛选；筛选后按稀有度 R→SR→SSR、来源无→偶像卡→支援卡、分类 A→M、计划不限→感性→理性→非凡、ID 升序排列。连续导入后返回主面板勾选定制项目并保存。移除卡牌只删除面板选择，不删除卡图或识别模板。

`config/hif_customization_catalog.json` 由固定的 [Gakumas Tools 数据提交](https://github.com/surisuririsu/gakumas-tools/tree/9ff4610011feb395e363d86d7c961e4da68b6deb)生成，只收录 237 张可定制的强化卡。每张卡保存卡牌 ID、名称、筛选字段，以及游戏菜单顺序中的 2～3 个定制项目 ID 和名称；不使用价格或等级。使用 `python sync_hif_customization_catalog.py` 更新目录，`--check` 核对目录；只有更新脚本需要联网，Maa 日常运行读取本地文件。

面板打开时显示主界面选定的「角色职业」，可切换好调、集中、好印象、元気、全力、強気。各职业独立保存导入卡牌和勾选的定制项目；切换时保留尚未保存的编辑，「保存配置」一次保存所有职业。移除卡牌只影响当前编辑的职业。导入目录与手动筛选仍共用。

面板将结果写入 `config/hif/hif_custom_card_selection.json` 的 `profiles.<职业>.<卡牌ID>`，值为勾选的定制项目 ID 数组。旧文件的顶层 `cards` 在首次面板保存时复制为六份独立职业配置，随后删除旧字段；保存前执行端继续兼容旧文件。存在 `profiles` 时，空白或缺失职业都使用空队列，不回退到其他职业或旧全局选择。

HIF 的 `ProduceHIFCardCustomAuto` 在执行时重新读取主界面职业对应的选择和目录，按卡牌 ID 找到名称，按定制项目 ID 找到原菜单序号；没有勾选项的卡不进入执行队列。每个职业队列最多处理前 6 张。识别先读卡名 OCR，读不出时比对已选卡的共享缩略图；旧 `config/cards_customize.json` 中已验证的卡面模板和 OCR 标记仍用作补充，不再提供菜单坐标或勾选状态。需要用实机日志核对新卡的命中结果。

## 通用菜单格位

用户提供的 2026-09-26 MuMu 截图覆盖「リスキーチャンス+」「ジャストアピール+」「頂点へ+」「達成感+」「本領発揮+」「テレビ出演+」「セッティング+」「アイドルになります+」的选卡页与定制执行页。720×1280 画面下，两项菜单占前两列，三项菜单占前三列；执行页按钮范围约为 x=40～240、260～460、480～680，y=890～990。自动点击取每列内部的 `(140,929)`、`(360,929)`、`(580,929)`，并沿用「合計あとN回」减少确认与卡住跳过逻辑。

这些截图验证了所列卡牌的菜单布局和定制项目顺序，可支持按序号通用点击。用共享缩略图比对 16 张截图时，正确卡的相关分数为 0.859～0.930，所列候选中的次高分最高为 0.600；程序用 0.83 阈值及 0.12 分差拒绝不确定匹配。这些静态结果不能证明全部 237 张卡的卡名 OCR、首次点卡后的页面过渡或执行结果；实机运行仍需核对日志与「合計」变化。多项已勾选时状态机会轮换尝试，剩余次数少于勾选项数时不保证每项都执行。
