# HIF 技能卡定制面板

工具栏「使用说明」独立介绍每个按钮、累计目标次数和项目上限。各项分块、标题加粗；打开说明后仍可编辑定制列表，主面板不展示大段说明。

「HIF培育」中显示的「HIF技能卡定制配置」是唯一前台入口，对应游戏日文「スキルカードカスタマイズ」。内部任务键仍为 `HIF自定义卡配置`，以保持已有任务配置可读。旧的逐卡任务选项不再显示，也不会迁移；已有面板配置仍保留。点击「导入卡牌」可按卡名、稀有度、计划、分类、来源、导入状态及定制项数组合筛选；筛选后按稀有度 R→SR→SSR、来源无→偶像卡→支援卡、分类 A→M、计划不限→感性→理性→非凡、ID 升序排列。连续导入后返回主面板设置各项目标次数并保存。移除卡牌只删除面板选择，不删除卡图或识别模板。

`config/hif_customization_catalog.json` 的卡牌列表固定于 [Gakumas Tools 数据提交](https://github.com/gakumas-tools/gakumas-tools/tree/c091aeae9f9637c25c4894340704f5dbad430c72)，收录 248 张可定制强化卡。每张卡保存卡牌 ID、名称、筛选字段，以及游戏菜单顺序中的 2～3 个定制项目 ID、名称和 `max` 上限。逐项上限来自 [固定的 customizations.csv](https://github.com/gakumas-tools/gakumas-tools/blob/c091aeae9f9637c25c4894340704f5dbad430c72/packages/gakumas-data/csv/customizations.csv)，修订记录在 `customizationRevision`。使用 `python tools/sync_hif_customization_catalog.py` 补充或核对上限（`--check` 仅检查），不改变卡牌列表和菜单顺序；只有维护脚本需要联网，Maa 日常运行读取本地文件。

面板打开时显示主界面选定的「角色职业」，可切换好调、集中、好印象、元気、全力、強気。各职业独立保存导入卡牌和各项目标次数；切换时保留尚未保存的编辑，「保存配置」一次保存所有职业。移除卡牌只影响当前编辑的职业。导入目录与手动筛选仍共用。

每项设置 **累计目标次数**，范围为 0～该项上限；0 表示不执行。目标包含已有定制，例如目标 2 次、已有 1 次时只补 1 次。新导入卡牌默认全部为 0。面板只校验逐项上限，不限制整卡目标次数之和；实际执行仍受游戏总剩余次数和 P 点限制。

面板将结果写入 `config/hif/hif_custom_card_selection.json`，顶层 `version` 为 2，`profiles.<职业>.<卡牌ID>` 的值是项目 ID 到累计目标次数的对象，例如 `{"73":2,"43":1}`。空对象保留导入卡牌但不加入执行队列。旧 ID 数组按各项上限转换，延续原勾选后尽量点满的意图；旧顶层 `cards` 在首次保存时复制为六份职业配置并删除旧字段。加载不会修改原文件，执行端继续兼容旧格式。存在 `profiles` 时，空白或缺失职业使用空队列，不回退到其他职业或旧全局选择。非法次数、无效项目或编辑期间文件被其他窗口修改时拒绝保存，并保留原文件。

HIF 的 `ProduceHIFCardCustomAuto` 在执行时重新读取主界面职业对应的选择和目录，按卡牌 ID 找到名称，按定制项目 ID 找到原菜单序号；所有目标为 0 的卡不进入执行队列。每个职业队列最多处理前 6 张。识别先读标题卡名 OCR，统一空白及全半角、保留强化标记 `+` 后仅作完整相等匹配；读不完整时比对已选卡的共享缩略图，不用子串、效果文字标记或文字相似度猜卡名。旧 `config/cards_customize.json` 中已验证的卡面模板仍用作补充，不再提供菜单坐标或目标次数。需要用实机日志核对新卡的命中结果。

点选候选卡后，必须确认当前格四个橙色选中角框、上方详情插画与当前格一致，以及识别卡名连续两帧一致，才允许进入定制或转向下一格。每次最多等待 5 秒，超时只重试当前格一次；仍未确认则记录未确认格位并跳过当前格，继续扫描下一张，绝不进入未确认卡的定制。扫描结束后正常返回商店继续培育；剩余目标记为未完成并附上跳过格位。取消任务时立即停止等待。卡面明显灰暗的不可定制卡跳过，即使标题带 `+` 也不视为可用。

2026-10-11 补充的八张选卡截图验证了前两行选中角框，其中七张可用卡的详情插画核对通过，一张不可定制灰态卡被跳过；把七张卡的旧详情与其他格选中框交叉组合，42 种错配均被拒绝。截图回放及模拟卡顿验证不能代替实机卡顿验收。

定制保留原有连续执行方式，不读取项目价格、不扣算余额，也不为检查余额额外返回商店。仅在名额为 0、准备刷新时连续两帧确认余额：低于 40 P 则结束剩余定制；刷新后重新读余额，余额减少即确认刷新成功，低于 40 P 则结束。余额未减少或无法确认时停止刷新和后续购饮，按既有开关回血并离店。扣款成功后若名额尚未显示，只观察等待，不重复刷新；有界等待后仍未确认则安全收尾。未完成目标记录原因，不计为完成。成功提示对 OCR 文本与预期文本统一执行空白、全半角及易混字符归一化（「ヘ→へ」「ー→一」），再校验完整名称和强化标记；不按具体卡名维护别名，不影响选卡识别。以上仍需 MuMu 实机验证。

定制提交后的通信错误每帧最多重试一次，不重放定制提交。识别到右下角 `CONNECTING` 或通信错误弹窗时，暂停结果判断，通信等待最多 30 秒；恢复后重新给予原操作 10 秒结果确认时间，整个确认阶段保留 40 秒观察上限。等待中不使用商店残影或过渡帧推进次数，超时保留待确认提交并保存现场；用户停止时不追加点击。以上为模拟时序回归结果，仍需 MuMu 网络异常场景验证。

## 通用菜单格位

用户提供的 2026-09-26 MuMu 截图覆盖「リスキーチャンス+」「ジャストアピール+」「頂点へ+」「達成感+」「本領発揮+」「テレビ出演+」「セッティング+」「アイドルになります+」的选卡页与定制执行页。720×1280 画面下，两项菜单占前两列，三项菜单占前三列；执行页按钮范围约为 x=40～240、260～460、480～680，y=890～990。自动点击取每列内部的 `(140,929)`、`(360,929)`、`(580,929)`，并沿用「合計あとN回」减少确认与卡住跳过逻辑。

这些截图验证了所列卡牌的菜单布局和定制项目顺序，可支持按序号通用点击。用共享缩略图比对 16 张截图时，正确卡的相关分数为 0.859～0.930，所列候选中的次高分最高为 0.600；程序用 0.83 阈值及 0.12 分差拒绝不确定匹配。这些静态结果不能证明全部 248 张卡的卡名 OCR、首次点卡后的页面过渡或执行结果。

执行端连续两帧读取各项目的「あとN回」或明确的「カスタマイズ上限」，用逐项上限减剩余次数计算已有次数，按菜单顺序轮换未达目标项目。每次只提交一项，通过完成提示或总次数减少确认成功，不把点击计作成功。达到全部目标后返回列表，不继续消耗总次数；总次数提前耗尽时记录各项未完成目标。逐项 OCR 未确认时有界等待，仍不确定则跳过当前卡，不猜测次数。次数功能的实机验收仍需核对逐项徽章、日志及实际定制结果。
