# HIF 战斗出牌优先级配置

每张卡的「后续卡」可设置按职业保存的组合：有序候选卡、0～6等待回合、初星黒酢检索、完成后再次等待，以及后续卡的「正常出牌／首次组合前保留／只用于衔接」。起始卡按普通优先级选择，确认打出后按候选顺序衔接；关闭再次等待时，同手候选仍可衔接，没有候选就恢复普通出牌。「只用于衔接」在完成或超时后也不允许后续卡单独出牌。原任务的等待设置已移除；旧值迁移到组级配置，冲突时须在面板选择后保存，原文件先备份。

组合保存在 `followup_profiles`。每组含 `targets`、`wait_turns`、`use_black_vinegar`、`wait_after_success`、`target_policy`。移除普通优先级仍保留组合和识别；未在卡表中的组合可在面板单独编辑。保存空组合表示关闭，不恢复旧国民／脚光规则。首次成功前，超时后再次打出起始卡仍可重试；等待中再次打出起始卡重置等待，但不重置本轮用醋额度。每轮最多用一瓶初星黒酢，按当前候选顺序寻找卡牌；首版不自动串联多段组合。成功记录和等待计数在每场战斗重置。

在 Maa 的「HIF培育」任务中，先选「角色职业」，再点「打开 HIF 战斗出牌优先级面板」。此配置决定 HIF 本战中已识别卡牌的出牌优先顺序，也可设置兜底优先级和全力职业的条件规则。主界面选「全力」会先显示全力；主界面选「集中」会先显示集中。在面板中可切换到另一职业并修改；保存会保留本次在各职业页签上的修改，不会改变主界面的职业选择。点「导入已有卡牌」可从全部强化卡及保留的旧卡条目中按卡面、筛选条件连续导入；无本战识别模板的卡会标为「无模板 · 仅卡名 OCR」，前缀冲突会单独提示；点卡片右侧「删除」只从当前职业的优先级表移除，卡牌识别、模板和展示图文件仍保留，因此以后可以重新导入。移除后若识别到该卡，出牌采用现有的未设置优先级兜底值。拖动卡片左侧手柄或用箭头调整顺序会重新编号；直接修改数字时卡片保持原位，保存成功后立即按数字从小到大排序，同级保持原有顺序。保存后，下次开始培育时生效。

每个职业顶部都有固定的「兜底优先级」设置，用于已识别但未单独配置优先级的卡，以及补认后仍暂未识别的卡，不提供删除操作。各职业的已登记卡都有「条件优先级」按钮，可设置生效优先级及「剩余回合 ≥ N」「剩余回合 ≤ N」。上下限同时勾选时按闭区间生效，例如 ≥3 且 ≤6；下限大于上限时拒绝应用。全力职业另有「全力值 < N」，回合区间与全力值可选「满足任一条件」或「同时满足」。未触发时按卡片原有优先级出牌；清除条件规则后也恢复原有优先级。「アッチェレランド+」打开规则窗口时会预填旧规则示例：剩余回合 ≤4 或全力值 <10 时为 7，但不会自动启用，必须主动应用并保存。战斗决策日志用「暂未识别」表示身份尚未确认，用「优先级来源」区分卡牌配置、未单独配置时的兜底和暂未识别时的兜底；用「按优先级拟出牌」表示尚未执行的选择，分别记录「条件优先级」与「使用限制」；后者会注明命中的条件组。

每个职业的已登记卡都有独立的「使用限制」按钮。每张卡最多配置三组条件：同组的当前状态与剩余回合门槛必须同时满足，三组之间满足任一组即可出牌。所有职业都能设置剩余回合门槛；全力、強気职业还可选「全力」「強気」「温存」当前状态。某组留空即不启用该组，三组均空表示无限制；识别不到状态或回合数时，该条件不满足。「使用限制」只决定卡是否进入出牌候选，不修改数字优先级。规则按职业和完整卡名保存在 `use_condition_profiles`。`羽ばたけ！+`、`わたしは、風！+`、`リスキーチャンス+` 不预填使用限制，也没有代码兜底。可自行设「羽ばたけ！+」仅全力状态、「わたしは、風！+」全力且剩余 ≤3 回合或強気且剩余 ≤1 回合、「リスキーチャンス+」剩余 ≤8 回合。未设置时这些卡不受状态和回合限制。左侧当前状态指针与右侧下回合状态提示分开识别，温存模板来自用户提供的 720×1280 战斗截图。前台保存后下次开始培育生效；游戏内结果由用户验证。

「HIF培育」任务新增「HIF优先获取卡配置」入口，打开后先显示主界面所选职业；也可在优先级面板中点击「优先获取卡」切换。优先获取卡页可删除已设卡，或从「导入优先获取卡」窗口按卡面和名称导入。导入列表提供强化卡及没有强化版的 LR 卡，并支持卡名搜索、稀有度、计划、分类、来源筛选和翻页；计划使用「不限／感性／理性／非凡」，分类使用「A 卡／M 卡／T 卡」，来源使用「无／偶像卡／支援卡」，其中「无」包含初始卡和培育卡。优先级和优先获取卡导入窗口筛选后均按 T 卡优先，再按稀有度 N→R→SR→SSR→LR、来源无→偶像卡→支援卡、分类 A→M、计划不限→感性→理性→非凡、ID 升序排列；优先级导入中的「眠気」属于 T 卡，排在最前。点击导入后窗口保持打开，可继续导入，最后返回主面板保存。相同卡名只显示一个条目；旧配置中的缩写匹配词原样保留，没有可靠的卡图对应时显示「无图」。已选优先获取名单不排序，换卡和技能卡领取仍按候选出现顺序寻找第一张命中优先获取卡。删除优先获取卡只修改当前职业的优先获取卡名单，不删除卡图或出牌识别模板。

面板与 HIF Agent 都读取程序数据目录下的 `config/hif/cards_priority.json`：`priority_profiles` 是各职业的显式优先级，`recognition_profiles` 是各职业继续识别的卡名，`unknown_priority_profiles` 是各职业兜底优先级（保留原字段名以兼容已有配置），`conditional_priority_profiles` 按职业保存条件规则。删除只改显式优先级及该卡的条件规则；导入时会把新卡加入识别名单。首次保存会留存 `config/cards_priority.before_visual_editor.json`；编辑期间若文件被其他窗口改动，保存会拒绝覆盖。空职业卡表表示没有独立卡片优先级，可从「集中」复制后配置。

优先获取卡名单保存在 `config/hif/cards_priority.json` 的 `preferred_acquisition_profiles` 中，按职业分别供授业换卡和技能卡领取读取。导入目录 `config/hif_target_card_catalog.json` 包含固定 Gakumas Tools `skill_cards.json` 的 429 张强化卡，以及修订 `4ff2efc4b66fc69c75c6f4ebf2b9690422883df8` 中 27 张无强化版 LR 卡，共 456 张。共享卡图目录 `resource/base/image/hif_card_icons/` 共 457 张，另含无强化版负面卡「眠気」(ID 23)。统一图源固定为 `gk-img` 修订 `1c0907223dcd9da1754aa435a50b893f4fc0f11f`。同 ID 优先取无后缀的 `<id>.webp`；缺失时保留 `<id>_8.webp`，本地统一保存为 `<id>.webp`。当前 457 张中，359 张来自无后缀文件，98 张在该提交中没有同 ID 无后缀缩略图而继续使用 `_8`。这些卡的 `_1`～`_13` 是人物变体，详情图也不能直接替代缩略图；完整名单见 [缺少无后缀图的 98 张卡](hif_icons_without_plain_source.md)。`config/hif_card_icon_sources.json` 逐 ID 固定源文件名与 SHA-256；两个同步脚本读取同一清单，检查时会拒绝重复 ID、缺项和文件内容不匹配。优先获取卡、优先级和技能卡定制面板按 ID 共用图片；图像仅用于前台展示，HIF 优先获取卡运行识别仍基于卡名 OCR。

任务开关「第二次授业：优先换出首次换入卡」对应 HIF 节点 `ProduceHIFSecondSwapPreferFirstAcquiredCardOut`；「第二次授业：相谈删除本次换入卡」对应 `ProduceHIFSecondSwapConsultDeleteAcquiredCard`。面板「HIF优先获取卡配置」读取 `preferred_acquisition_profiles`。旧任务选项键、旧节点键和旧名单字段已清理；本机旧开关状态未迁移，新开关从默认关闭开始。

「HIF培育」新增「HIF授业优先换出卡配置」入口，打开后先显示主界面所选职业。该页从现有 HIF 卡图库（含 T 卡「眠気」）筛选导入，支持删除及上下移动；名单从上到下决定换出优先级。名单按职业保存在同一配置文件的 `swap_out_priority_profiles`，每项为完整卡名；缺少该键或名单为空时沿用原规则，不迁移已有优先获取卡名单。第一次授业换出按面板顺序找卡，再找“基本”卡；开启任一授业换卡开关后的第二次换出，先找第一次换进的记录卡 `a`，再找面板名单，最后找“基本”卡。程序逐格点卡并等待卡名稳定，按严格卡名标准化匹配；多张名单卡同时出现时以面板顺序为准，不以卡格位置为准。点击「チェンジ」后仍需确认交换页关闭才推进换卡次数。实机效果由用户验证。

优先级导入目录 `config/hif_priority_card_catalog.json` 包含上述 456 张卡及「眠気」，共 457 个卡名键；旧配置中的「夏夜に咲く想+」已统一为正式卡名「夏夜に咲く思い出+」，各职业原有优先级保留。原有卡片保留已验证的 OCR 前缀和识别模板，新加入的 LR 条目使用无模板的短前缀 OCR，需以实机识别结果验证；导入窗口会提示 OCR 前缀冲突。新增卡时，由维护者按识别需要制作 `resource/base/image/cards/` 下的模板，并在目录中登记卡名、OCR 前缀和模板；随后补齐 `config/hif_priority_card_images.json` 中同名卡的图片 ID。使用 `sync_hif_priority_images.ps1` 校验统一目录。各导入窗口点击「导入」后均保持打开，已加入项禁用，搜索与页码保留；改动仍只在主面板点击「保存」后写入。展示图与识别模板分开。

## 前台源码与打包

当前运行包的前台源码基线为 MFAAvalonia `v2.14.0`。任务设置入口与原生窗口在开发仓库的 `frontend/` 中直接维护。执行 `python tools/hif_build.py build` 会编译该源码并生成独立运行包；修改后的源码与 HIF 扩展一起审查、提交。构建及前台升级流程见仓库根目录的 `docs/hif/使用与构建.md`，不再维护或应用前台补丁。

入口只在 HIF 的 `Produce` 任务上出现；任务选项分别位于 `extensions/hif/tasks/produce_hif.json`。逐卡定制任务选项已从主界面移除，改用独立的 HIF 技能卡定制面板。前台加载、复制、保存、冲突和失败日志使用 MFAAvalonia 的 `LoggerHelper`，写入 `logs/log-YYYYMMDD.log`，操作标识为 `HifPriorityEditor`。HIF Agent 的出牌读取仍由 `extensions/hif/agent/hif/action/produce.py` 完成。

## 组合、关联与额外回合

后续卡和饮料关联卡的添加窗口支持卡名、稀有度、计划、分类、来源筛选和分页；排列与普通导入一致：T 卡优先，随后按稀有度 N→R→SR→SSR→LR、来源、A/M 分类、计划和 ID 排序。已选候选列表保留手动设置的衔接顺序。特製ハツボシエキス仍只允许关联 A 卡。主列表只显示配置入口及已配置标记，候选卡名和顺序点入窗口查看；后续卡按钮与使用限制同一行。

卡牌「使用限制」内的「有额外回合时不使用」按职业、完整卡名保存到 `no_extra_turn_profiles`。勾选后，只要左上角仍有待兑现的白底蓝字「+N」，该卡就不进入普通、组合衔接或兜底候选；无法确认标记时也先保留。标记消失并转为倒计时后恢复普通规则，不表示禁止在额外回合阶段使用。

额外回合储备与倒计时环分别读取。倒计时 1 结束后，连续两帧确认「+N」消失且环变成 N，才确认储备转入；N=1 时数字保持 1，也能确认真实空过。转入后的 N 不再与旧储备重复相加，异常跳变仍拒绝。独立识别节点 `ProduceHIF__ProduceExtraTurns` 返回 `extra_turns`（正整数、0 或 null）与 `confirmed`，不执行出牌或用饮；0 表示当前没有待兑现标记，null 表示未确认。

授业入口仅在日期计数6（第一次）或3（第二次）、且三列「授業」按钮均已识别时触发。动作重新确认日期与按钮后才记录授业阶段；开局、转场或日期不明时不默认点Vo、不推进次数。支给技能卡只读取详情第一行卡名，排除类型图标和下方效果，并连续确认后按完整卡名匹配名单。
