# HIF 战斗出牌优先级配置

各标签的说明由「HIF 策略」页顶部「使用说明」在右侧抽屉中显示，随标签切换，不阻挡编辑；每个选项分开成块，标题加粗，正文分段。条件优先级、使用限制的说明并入出牌优先级的说明，出牌编排有独立说明；编辑区只保留设置、状态和必要的操作确认。

「兜底优先级」下方的「未配置卡偏好」按职业保存，可选不偏好类型（默认）、全场优先 M、全场优先 A、按剩余回合切换。切换模式可设收尾门槛（1～99，预填 3），前期和收尾各选不偏好／M／A；剩余回合小于等于门槛时使用收尾偏好，回合未确认时不应用类型偏好。只调整未单独配置卡之间的同级顺序，已配置卡的数字优先级、条件规则与使用限制继续生效。

「优先使用强化卡」默认关闭，可独立启用。不偏好类型时，未配置卡同级优先强化；有类型偏好时先比较类型，再比较强化。已配置卡以及组合衔接选定卡名后，多张同名手牌优先强化版，不改变不同卡名的顺序。强化按实际读到的卡名末尾 `+` 判断（含 `++`、全角 `＋`）；完整素卡名无 `+` 为未强化，截断或模板识别未确认时不猜测，也不把目录中的强化版卡名当成实际手牌的强化证据。设置保存在 `unconfigured_card_preference_profiles`，包含在职业分享文件内；旧配置和旧分享文件缺少设置时保持无偏好、强化开关关闭，保存后下次开始培育生效。

「出牌编排」按职业以起始卡为单位设置出牌前后用饮和组合衔接：

- 起始卡被选中出牌时，先按顺序喝它的「前置」饮料，重新找到这张卡打出；打出后仍是同一回合、还在战斗页时再喝「后置」饮料，回合已结束（通常每回合只能出一张卡）就跳过。
- 「后续候选」有序：起始卡确认打出后，衔接第一张在手牌且符合使用限制的候选，打完这一张组合完成，不依次打出全部候选。衔接时只用该候选位置的前置、后置饮料；普通出牌不使用这些位置。没有候选的编排只给这张卡前后用饮。
- 组合设置：等待回合 0～6（候选都不在手牌时最多空过几回合，0 不空过，同手有候选时仍衔接）、再次等待（完成一次组合后再遇到起始卡是否继续等待）、后续卡出牌（可单独出／首次组合前保留／只用于衔接）。准备空过等待前喝一轮「等待用饮」，每次衔接一轮；编排用饮后出现选卡页时按后续候选顺序选卡。
- 每个饮料位置可放多瓶，按顺序各喝一瓶；全部 28 种饮料都能选。饮料栏里没有、已达到一战单种或总上限、或该场关闭的饮料跳过，照常出牌，不补喝；整栏确认没有某种饮料后，本场编排不再为它扫描饮料栏。编排用到的饮料仍按饮料面板的时机使用，设为「只在出牌编排中使用」时才只在编排里喝。
- 前置饮料用过后若这张卡未能打出（重新识别超时），解除锁定，本场这张卡不再用前置饮料。

编排保存在 `play_sequence_profiles.<职业>.<起始卡>`：`targets`（有序候选，可为空）、`wait_turns`、`wait_after_success`、`target_policy`，以及 `drinks` 下的 `before`、`after`、`waiting` 和 `targets.<候选>.before/after`（饮料名数组）。没有候选也没有起始卡饮料的编排保存时去掉；没有候选时不能设等待用饮；组合不能形成循环。Agent 与面板按同一规则校验（`extensions/hif/followups.py` 的 `validate_sequences`、`HifPlaySequenceConfig`）。首次成功前，超时后再次打出起始卡仍可重试；等待中再次打出起始卡重置等待，但不重置本轮等待用饮。成功记录和等待计数在每场战斗重置。

旧版后续卡（`followup_profiles`）、组合的初星黒酢开关和饮料面板的特製ハツボシエキス「关联卡牌」不迁移：读取时忽略并提示「后续卡」「饮料」含旧版本格式，保存时去掉，需要在出牌编排中重新设置。旧任务等待值和旧全局 `combo`/`skip_limit` 同样忽略并提示「出牌优先级」。编排中引用的卡或饮料不在目录中时，该职业的编排忽略并提示「出牌编排」，面板照常打开。公开默认的集中「国民的アイドル+ → 脚光+」改为出牌编排，等待用饮为初星黒酢；已有个人配置不会被覆盖。

在 Maa 的「HIF培育」任务中，先选「角色职业」，再点任务设置中的「HIF 策略」按钮或从左侧导航进入「HIF 策略」页，选「出牌优先级」标签。此配置决定 HIF 本战中已识别卡牌的出牌优先顺序，也可设置兜底优先级和全力职业的条件规则。进入页面时先显示任务所选职业（主界面选「全力」会先显示全力）。可在页面顶部切换到另一职业并修改；保存会保留本次在各职业上的修改，不会改变主界面的职业选择。出牌优先级、授业换出卡、出牌编排三个标签共用同一份编辑数据（「获取与定制」中的优先获取开关也写入这份数据），切换标签不丢失修改，有修改的标签名后显示「•」；顶部「保存」一次写入所有面板，「放弃修改」重新读取已保存的配置；任务运行中页面只读。

出牌优先级为左右两栏，兜底优先级、未配置卡偏好和保留等职业通用设置在两栏上方。左侧卡表定宽（可拖动分隔线调整），可拖动排序、直接改基础优先级，并标出已设的条件优先级、使用限制、出牌编排和保留；点一张卡后，右侧详情随窗口伸缩：标题行为卡图、卡名、顺位和上移、下移、从卡表移出、保留（宽度不够时按钮换行）；下面「条件优先级」「使用限制」两张卡片同时显示并就地编辑，卡片右上角标出当前规则摘要或「未设置」，详情够宽时左右并排，不够宽时上下叠放；最下一行为出牌编排的摘要和「编辑出牌编排」（没有编排时为「为这张卡新建出牌编排」），点击切到「出牌编排」标签。

「出牌编排」为独立标签：左侧顶部「新建组合」，下面列出已有编排的起始卡（包括不在出牌卡表中的卡），显示后续卡小图和摘要；右侧为卡与饮料组成的顺序：前置 → 起始卡 → 后置，下方为竖排后续候选（各自的前置 → 候选 → 后置，可上移、下移、移出），末尾「添加后续卡」。点「新建组合」、起始卡（更换起始卡）、「添加后续卡」或某个位置的「＋」，在标签内打开选择区：选卡用与卡库相同的筛选网格（会形成循环的卡变灰，已有编排的卡标「编」），选饮料列出全部 28 种饮料（按饮料面板设置不会被喝的标出原因，仍可加入）；点选按顺序加入，再点一次移出，「完成」关闭。已选饮料点一下移出。有后续候选时下方显示组合设置与等待用饮；「删除编排」移除该起始卡的全部设置。修改直接计入页面的未保存状态，顶部「保存」写入。

页面标签依次为出牌优先级、获取与定制、授业换出卡、出牌编排、卡库、饮料；任务设置中只有一个「HIF 策略」按钮，打开本页并切到任务所选职业，停在上次所在的标签。加卡统一在「卡库」进行，名单为空时提供「打开卡库添加」（获取与定制相同），有卡后不显示。授业换出卡的名单排成等宽卡片（与饮料页「其他饮料」相同），按页面宽度分列并铺满整行，页面变宽或变窄时每行张数随之变化，卡片显示卡图、卡名和稀有度 · 计划 · 类型，点右上角 × 移出，卡图左侧标出顺位，用 ← → 前移或后移，卡片下方为「优先换出未定制版本」「允许换出定制版本」两个开关。职业配置的导入导出在页面顶部「职业配置」菜单。页面顶部「使用说明」在右侧打开说明抽屉，内容随标签切换，可与编辑同时查看。

「卡库」标签按职业列出全部卡牌：先选「点卡加入」的名单（出牌优先级、获取与定制、授业换出卡），再点卡加入，再点一次移出；出牌编排的起始卡和后续卡在「出牌编排」标签的选择区中选。默认只看当前职业计划与不限（好调/集中为感性，好印象/元気为理性，全力/強気为非凡），同计划另一职业在用的卡排在最前；可按卡名、稀有度、类型、来源、计划（感性、理性、非凡、不限）筛选，除卡名外每项都可多选（如稀有度同时选 SSR 与 SR），点「全部」取消该项筛选，「只看…与不限」开关与这些筛选叠加生效；蓝框表示已在所选名单；卡图右上角的角标（出、获、定、换，各自一个小块）标出已在哪些名单，与所选名单无关，选择行右侧有图例。名单为空时的「打开卡库添加」会跳到卡库并选好名单。卡库包含全部强化卡、无强化版 LR 卡及保留的旧卡条目，悬停可看稀有度、计划、类型、来源和已在的名单。在卡牌详情点「从卡表移出」只从当前职业的优先级表移除，卡牌识别、模板和展示图文件仍保留，以后可以重新加入。移除后若识别到该卡，出牌采用现有的未设置优先级兜底值。拖动卡片左侧手柄或在详情中上移、下移会重新编号；直接修改数字时卡片保持原位，保存成功后立即按数字从小到大排序，同级保持原有顺序。保存后，下次开始培育时生效。

每个职业顶部都有固定的「兜底优先级」设置，用于已识别但未单独配置优先级的卡，以及补认后仍暂未识别的卡，不提供删除操作。卡牌详情的「条件优先级」可设置生效优先级及「剩余回合 ≥ N」「剩余回合 ≤ N」。上下限同时勾选时按闭区间生效，例如 ≥3 且 ≤6；下限大于上限时拒绝应用。全力职业另有「全力值 < N」；全力与強気职业另有「指针状态」，可勾选全力、強気、温存中的一个或多个，当前指针为任一勾选状态时满足，未识别时不满足。这两个职业的回合区间、全力值与指针状态可选「满足任一条件」或「同时满足」。未触发时按卡片原有优先级出牌；清除条件规则后也恢复原有优先级。「アッチェレランド+」未设条件优先级时，详情中会预填旧规则示例：剩余回合 ≤4 或全力值 <10 时为 7，但不会自动启用，必须主动应用并保存。战斗决策日志用「暂未识别」表示身份尚未确认，用「优先级来源」区分卡牌配置、未单独配置时的兜底和暂未识别时的兜底；用「按优先级拟出牌」表示尚未执行的选择，分别记录「条件优先级」与「使用限制」；后者会注明命中的条件组。

卡牌详情的「使用限制」按卡设置，每张卡最多配置三组条件：同组的当前状态与剩余回合门槛必须同时满足，三组之间满足任一组即可出牌。所有职业都能设置剩余回合门槛；全力、強気职业还可选「全力」「強気」「温存」当前状态。某组留空即不启用该组，三组均空表示无限制；识别不到状态或回合数时，该条件不满足。「使用限制」只决定卡是否进入出牌候选，不修改数字优先级。规则按职业和完整卡名保存在 `use_condition_profiles`。`羽ばたけ！+`、`わたしは、風！+`、`リスキーチャンス+` 不预填使用限制，也没有代码兜底。可自行设「羽ばたけ！+」仅全力状态、「わたしは、風！+」全力且剩余 ≤3 回合或強気且剩余 ≤1 回合、「リスキーチャンス+」剩余 ≤8 回合。未设置时这些卡不受状态和回合限制。左侧当前状态指针与右侧下回合状态提示分开识别，温存模板来自用户提供的 720×1280 战斗截图。前台保存后下次开始培育生效；游戏内结果由用户验证。

优先获取卡在「获取与定制」标签中用每张卡片上的「优先获取」开关设置（见 `hif_custom_card_panel.md`），从任务设置的「HIF 策略」按钮或左侧导航进入，先显示任务所选职业。卡牌在「卡库」选「获取与定制」后点卡加入：卡库提供强化卡及没有强化版的 LR 卡（只在出牌优先级目录中的旧条目和 T 卡不能加入），可按卡名、稀有度、类型、来源、计划筛选（可多选），默认只看当前职业计划与不限。相同卡名只显示一个条目；旧配置中的缩写匹配词原样保留，没有可靠的卡图对应时显示「无图」。已选优先获取名单不排序，换卡和技能卡领取仍按候选出现顺序寻找第一张命中优先获取卡。移出优先获取卡只修改当前职业的优先获取卡名单，不删除卡图或出牌识别模板。

面板与 HIF Agent 都读取程序数据目录下的 `config/hif/cards_priority.json`：`priority_profiles` 是各职业的显式优先级，`recognition_profiles` 是各职业继续识别的卡名，`unknown_priority_profiles` 是各职业兜底优先级（保留原字段名以兼容已有配置），`conditional_priority_profiles` 按职业保存条件规则。从卡表移出只改显式优先级及该卡的条件规则；保存时把卡表和出牌编排中的卡加入识别名单。编辑期间若文件被其他窗口改动，保存会拒绝覆盖。空职业卡表表示没有独立卡片优先级，可从「集中」复制后配置。

优先获取卡名单保存在 `config/hif/cards_priority.json` 的 `preferred_acquisition_profiles` 中，按职业分别供授业换卡和技能卡领取读取。卡库目录 `extensions/hif/catalog/hif_target_card_catalog.json` 包含固定 Gakumas Tools 修订 `2371156ba7db7e3fc9d62e13dc47d7956125f6ea` 中 `csv/skill_cards.csv` 的 443 张强化卡，以及 27 张无强化版 LR 卡，共 470 张。共享卡图目录 `extensions/hif/resource/base/image/hif/hif_card_icons/` 共 471 张，另含无强化版负面卡「眠気」(ID 23)。统一图源固定为 `gk-img` 修订 `8d55c4ba6b69411586a0803feacc737c4e2d4508`。同 ID 优先取无后缀的 `<id>.webp`；缺失时保留 `<id>_8.webp`，本地统一保存为 `<id>.webp`。当前 471 张中，373 张来自无后缀文件，98 张在该提交中没有同 ID 无后缀缩略图而继续使用 `_8`。这些卡的 `_1`～`_13` 是人物变体，详情图也不能直接替代缩略图；完整名单见 [缺少无后缀图的 98 张卡](hif_icons_without_plain_source.md)。`extensions/hif/catalog/hif_card_icon_sources.json` 逐 ID 固定源文件名与 SHA-256；`tests/test_hif_card_catalogs.py` 按该清单检查重复 ID、缺项和文件内容不匹配。优先获取卡、优先级和技能卡定制面板按 ID 共用图片；图像仅用于前台展示，HIF 优先获取卡运行识别仍基于卡名 OCR。

任务开关「第二次授业：优先换出首次换入卡」对应 HIF 节点 `ProduceHIFSecondSwapPreferFirstAcquiredCardOut`；「第二次授业：相谈删除本次换入卡」对应 `ProduceHIFSecondSwapConsultDeleteAcquiredCard`。「获取与定制」标签的「优先获取」开关读写 `preferred_acquisition_profiles`。旧任务选项键、旧节点键和旧名单字段已清理；本机旧开关状态未迁移，新开关从默认关闭开始。

「授业换出卡」标签先显示任务所选职业，在「卡库」选「授业换出卡」后点卡加入（可选 T 卡「眠気」），支持移出及前移、后移；卡片顺序（卡图左侧的顺位）决定换出优先级。名单按职业保存在同一配置文件的 `swap_out_priority_profiles`，每项为完整卡名；缺少该键或名单为空时沿用原规则，不迁移已有优先获取卡名单。第一次授业换出按面板顺序找卡，再找“基本”卡；开启任一授业换卡开关后的第二次换出，先找第一次换进的记录卡 `a`，再找面板名单，最后找“基本”卡。程序逐格点卡并等待卡名稳定，按严格卡名标准化匹配；多张名单卡同时出现时以面板顺序为准，不以卡格位置为准。点击「チェンジ」后仍需确认交换页关闭才推进换卡次数。实机效果由用户验证。

出牌优先级目录 `extensions/hif/catalog/hif_priority_card_catalog.json` 包含上述 470 张卡及「眠気」，共 471 个卡名键；旧配置中的「夏夜に咲く想+」已统一为正式卡名「夏夜に咲く思い出+」，各职业原有优先级保留。原有卡片保留已验证的 OCR 前缀和识别模板，新加入的 LR 条目使用无模板的短前缀 OCR，需以实机识别结果验证。新增卡时，由维护者按识别需要制作 `extensions/hif/resource/base/image/hif/cards/` 下的模板，并在目录中登记卡名、OCR 前缀和模板；随后补齐 `extensions/hif/catalog/hif_priority_card_images.json` 中同名卡的图片 ID，并运行 `tests/test_hif_card_catalogs.py` 校验统一目录。在卡库点卡加入后可继续点选，再点一次移出；改动只在页面顶部点「保存」后写入。展示图与识别模板分开。

授业优先换出卡的每张卡条目有「优先换出未定制版本」和「允许换出定制版本」两个开关，按职业、卡名独立保存。两个开关均默认开启：同名卡先选未定制版，找不到时允许选定制版；关闭优先开关后，同名版本按卡格顺序选择；关闭允许开关后，该卡定制版在记录卡匹配、名单、基本卡和兜底换出中都会跳过。卡牌名单顺位仍优先于版本顺位。

规则保存在 `swap_out_options_profiles`，不包含在战斗职业配置分享文件中。旧配置缺少字段时按两个开关都开启处理，已有名单、顺序和其他配置保留；保存过的关闭值不会被默认值重置。没有逐卡设置的卡也使用这两个默认值。

日志分别记录「有定制标记」与「定制标记未确认」。标记未确认时按非定制卡处理，参与普通版优先匹配与换出；只有明确识别出定制标记时才应用该卡的定制版许可。

## 按职业分享配置

在页面顶部选择职业，点「职业配置」菜单中的「导出当前职业配置…」，保存为 JSON 文件即可分享。导出的是该职业当前编辑的战斗配置，包含出牌优先级、未知卡优先级、条件优先级、使用限制、出牌编排（`play_sequences`）和额外回合限制；不包含优先获取和换出名单、其他职业、饮料、技能卡定制或模拟器连接设置。

接收方选择文件对应的职业，点「职业配置」菜单中的「导入职业配置…」。检查通过后会显示卡牌数量和替换范围，点「替换本职业的编辑配置」，检查或调整后点页面顶部「保存」生效；取消导入或「放弃修改」时原文件保持不变。导入会替换该职业的上述战斗配置，优先获取和换出名单及其他职业的编辑内容保留；旧分享文件即使带有获取或换出名单，也会忽略这些字段；旧分享文件中的后续卡组合（`followups`）不导入，确认窗口会说明，缺少出牌编排时按空编排导入。职业不匹配、文件版本不支持、未知或重复卡牌及无效规则会拒绝导入并显示原因；卡牌目录缺项时先使用包含所需卡牌的完整版本。卡面和识别资源使用接收方本地目录，无需随分享文件发送图片。

## 前台源码与打包

当前运行包的前台源码基线为 MFAAvalonia `v2.16.4`。任务设置入口与「HIF 策略」页在开发仓库的 `frontend/` 中直接维护。执行 `python tools/hif_build.py build` 会编译该源码并生成独立运行包；修改后的源码与 HIF 扩展一起审查、提交。构建及前台升级流程见仓库根目录的 `docs/hif/使用与构建.md`，不再维护或应用前台补丁。

入口只在 HIF 的 `Produce` 任务上出现；任务选项分别位于 `extensions/hif/tasks/produce_hif.json`。逐卡定制任务选项已从主界面移除，改用「HIF 策略」页的「获取与定制」标签。前台加载、复制、保存、冲突和失败日志使用 MFAAvalonia 的 `LoggerHelper`，写入 `logs/log-YYYYMMDD.log`，操作标识为 `HifPriorityEditor`。HIF Agent 的出牌读取由 `extensions/hif/agent/hif/action/` 下的战斗模块（`battle_decision.py` 等）完成，`produce.py` 只负责导入注册。

## 出牌编排与额外回合

出牌编排的选卡区与卡库共用 `HifCardPicker`：按卡名、稀有度、类型、来源、计划（均可多选）与当前职业计划开关筛选，出牌卡表中的卡排在最前，只生成可见行。已选候选保留点选顺序，可在顺序中上移、下移。

卡牌「使用限制」内的「有额外回合时不使用」按职业、完整卡名保存到 `no_extra_turn_profiles`。勾选后，只要左上角仍有待兑现的白底蓝字「+N」，该卡就不进入普通、组合衔接或兜底候选；无法确认标记时也先保留。标记消失并转为倒计时后恢复普通规则，不表示禁止在额外回合阶段使用。

额外回合储备与倒计时环分别读取。倒计时 1 结束后，连续两帧确认「+N」消失且环变成 N，才确认储备转入；N=1 时数字保持 1，也能确认真实空过。转入后的 N 不再与旧储备重复相加，异常跳变仍拒绝。独立识别节点 `ProduceHIF__ProduceExtraTurns` 返回 `extra_turns`（正整数、0 或 null）与 `confirmed`，不执行出牌或用饮；0 表示当前没有待兑现标记，null 表示未确认。

授业入口仅在日期计数6（第一次）或3（第二次）、且三列「授業」按钮均已识别时触发。动作重新确认日期与按钮后才记录授业阶段；开局、转场或日期不明时不默认点Vo、不推进次数。支给技能卡只读取详情第一行卡名，排除类型图标和下方效果，并连续确认后按完整卡名匹配名单。

## 保留与移动页

全力与強気职业在卡牌详情中有「保留」勾选，职业顶部有「按优先级保留」开关（默认关闭）。两项按职业保存到 `hold_priority_profiles`：`{"ordered": false, "cards": [...]}`，`cards` 按卡表从上到下的顺序保存勾选卡；从卡表移出的卡不再保存。旧配置没有该字段时按空名单、先找到先保留处理。职业分享文件新增 `hold_priority`，旧分享文件没有该字段时按空名单导入；其他职业的分享文件不能带保留卡。

保留页的来源按最近一次动作判断：全力/強気确认打出的卡，或正在使用的饮料。来源只决定页面操作方式，选卡都用同一份名单：

| 来源 | 名单为空 | 找到勾选卡 | 有勾选但都未找到 |
|---|---|---|---|
| 「本領発揮+」（可选两张，点一次看详情，再点一次选中） | 保留第一格 | 最多选两张后移动 | 点取消 |
| 其他出牌、未知来源、「ほっと緑茶」 | 选第一格 | 选一张后移动 | 选第一格 |

「按优先级保留」关闭时，扫描中先找到的勾选卡即选，找够即停；开启时扫描整个卡组，按卡表顺序取最靠前的（找到第一顺位即停）。「ほっと緑茶」在任何职业都按该职业名单处理，其他职业名单为空，即选第一格。原全力「モチベ+」写死的四张目标与「本領発揮+」写死的两张目标已移除，需要时在面板勾选。

出牌编排中的起始卡前置、后置饮料和等待用饮若打开选卡页，按该编排的后续候选顺序选卡，不使用保留名单；候选位置的饮料、其他职业或饮料普通时机的移动页仍找「脚光」，找不到选第一格。

移动/保留页的卡组可上下滚动。进入页面时先看首行上方是否为浅灰空详情板：是则首行中心 y≈569、行距 147（2026-11-03 ほっと緑茶 实机截图测得），卡组超过一屏时慢速上滑约一行，用滑动前后列表区图像测实际位移（与授业换出共用 `common._hif_list_scroll_shift`），只扫新露出的行；位移无法确认时滑回顶部，仍无法确认则不再按坐标点卡。否则按首行 y≈457 的旧版式只扫可见三行。2026-11-01 21:32 的日志显示旧格位 y=457 在当前移动页会点到上方详情区并打开「スキルカード詳細」，因此不再固定使用旧格位。点卡后等标题连续两次读到相同卡名才记录；选中前回到该卡并复核卡名，不符时不移动。滚动、版式判断和本領発揮的两次点击尚待 MuMu 实机验证。
