# HIF 使用与构建

## 配置

运行包中的 HIF 固定本战、跳过选偶像，默认集中、一次培育、不使用体力药、不跳过准备。新解压目录首次打开只有「一键培育」实例和「HIF培育」任务，任务选项沿用维护者已确认的测试设置；模拟器连接需要自行设置。

公开首次启动模板位于 `extensions/hif/first-run/`：`config/config.json` 是界面设置，`config/instances/hif.json` 是不含设备信息的 HIF 实例和任务选项，`resource/mfa_layout.json` 是界面布局。构建时复制到新运行包；手动更新已有版本时保留整个 `config/` 和本地 `resource/`，不会用模板覆盖个人配置。

五个面板分别维护出牌、获取卡、换出卡、饮料、技能卡定制。公共默认值仅包含集中职业的现有策略，其他职业保留空表。首次初始化从 `extensions/hif/defaults/` 复制到 `config/hif/`；文件已存在时不覆盖。

## 一键备份与导入设置和个人策略

完全退出前台后，在程序目录双击 `export_settings_导出设置.bat`。备份保存到 `backup/maa-settings-时间戳-编号.zip`，包含整个 `config/`（界面设置、连接、任务选项、全部职业策略及旧版策略文件）、`appsettings.json`（实例列表与定时任务）和 `resource/mfa_layout.json`（布局）；后两项不存在时跳过。附带文件 SHA-256 清单和恢复说明，源文件保持原样，不包含程序、日志和游戏资源。

更新时将完整安装包解压到新目录，关闭新旧前台，在新版目录双击 `import_settings_导入设置.bat` 并选择备份 ZIP，也可直接将 ZIP 拖到脚本上。导入先检查文件路径和 SHA-256，再将目标目录现有设置备份到 `backup/`，最后合并目录、替换备份内的同名设置文件；失败回滚已写入文件，未出现在备份中的新版配置文件保留。旧版策略迁移仍按下方「旧版迁移」操作。删除旧目录前，将备份 ZIP 另存到旧目录之外；备份含个人连接信息，请自行保存。

命令行可用 `export_settings_导出设置.bat --no-pause`。PowerShell 入口 `tools/export_settings.ps1` 支持 `-Root` 指定程序目录、`-OutputDirectory` 指定备份目录。脚本拒绝导出仍在运行的本目录前台，以及配置中的链接或目录联接；仅备份已保存的内容。脚本随新运行包及手动脚本更新提供。

导入命令为 `import_settings_导入设置.bat "备份.zip" --no-pause`；PowerShell 入口 `tools/import_settings.ps1` 支持 `-Root`、`-ArchivePath`，未指定 ZIP 时弹出选择窗口。只导入本工具生成且校验通过的备份，不替换新版任务定义、程序或资源。

新版启动时由前台按新版任务定义同步选项：保留同名旧选项的选择，为新增选项及当前分支的新增子选项补默认值，移除不再定义的顶层选项。选项改名会按新选项初始化；下拉选择按序号保存，候选重排或删除时须核对。新增任务不会自动加入已有任务列表，需要手动添加。导入脚本不改写策略内容，策略格式的专门迁移仍依赖对应版本的迁移工具。

## 清理日志与诊断图片

完全退出前台后，在程序目录双击 `clear_logs_清除日志.bat`。脚本清理 `logs/`、`debug/` 下的 `.log`、`.log.zip`，以及 `debug/` 下的 PNG、JPEG、BMP、WebP 诊断图片；保留文件夹、配置、资源、其他备份和验证 JSON。不会进入链接或目录联接，锁定文件保留并报告。

```powershell
# 先预览；不会删除文件。
.\clear_logs_清除日志.bat --dry-run
# 可选：同时删除新旧配置目录中的编辑前快照；不删除 cards_priority.json。
.\clear_logs_清除日志.bat --priority-backup
```

批处理保留旧脚本的参数，增加 `--no-pause` 供命令行调用。PowerShell 入口为 `tools/clear_logs.ps1`，支持 `-Root` 指定要清理的程序目录及 `-DryRun`、`-PriorityBackup` 参数。脚本随新运行包及手动脚本更新一起提供。

## 自动检查与完整包更新

首次升级到 v261009.2 须将完整包解压到新目录，完全退出旧版，使用一键备份和导入迁移设置。旧版更新器不能替换前台和运行时。此后设置 → 版本更新提供「检查 HIF 更新」「更新 HIF 完整包」「取消更新」和本地 ZIP 更新。手动点击先检查版本，有新版时展示版本号和 Release 更新说明，确认后才下载；没有新版明确提示无更新。自动检查发现新版同样展示说明，自动安装关闭时等待确认，开启时后台下载并可取消。

复用 Maa 已有开关。首次升级开启自动检查并提示，自动安装保持关闭；之后尊重用户选择。启动时和持续运行每 6 小时检查，手动检查不限间隔。自动更新开启后发现新版会下载，等待所有实例的任务队列及执行过程结束、策略编辑窗口保存并关闭，再显示可取消的 10 秒倒计时。无限循环任务不会被更新中断；下载后主动退出，本次不安装，下次打开提示继续。

下载与校验期间前台可继续使用。安装前保存全部实例、任务、全局设置和布局，禁止启动新任务并暂停定时触发；保存失败中止安装。独立 PowerShell 程序确认前台退出后，先备份配置，再按清单替换程序、前台和运行时，自动导入并启动新版。新版加载实例、任务定义和配置后返回成功确认；启动失败或 120 秒未确认时恢复旧程序及原配置。本次更新重启不自动执行任务，原有启动偏好保留。

备份与旧程序文件保存在 `backup/hif-update-操作编号/`，成功后清理本次下载和解压文件；失败记录保留。断电或更新中断后，完全退出前台，双击 `recover_update_恢复更新.bat` 恢复。需要只恢复不启动时，可在 PowerShell 调用保存的安装程序，传入 `-OperationPath`、`-Recover -NoRestart`。程序清单只管理已知发行文件，清单外文件、个人插件、日志和备份不删除；旧版缺少清单时不猜测删除旧文件。

只读取本 Fork 的稳定 HIF Releases，不独立更新官方前台或 MaaFramework。更新包附 `hif-package-manifest.json` 和同名 `.zip.sha256`；系统缺少新版需要的 .NET 时在退出前提示安装，客户端不自行安装系统依赖。命令行本地更新可运行 `MaaGakumasu.exe --hif-update-package "安装包.zip"`，旁边须有同名 SHA-256 文件。

维护者验证命令：`python -m unittest discover -s tests -p test_full_update.py -v`；编译后的原生策略验证使用 PanelQa 的 `--full-update-policy-only`，完整运行测试使用 `python tools/run_full_update_smoke.py --runtime 已构建运行目录 --frontend 新前台发布目录`。这些测试使用独立目录，不运行游戏。

## v261008.2 升级记录

本版包含前台修复与新版图标。请将完整 ZIP 解压到新目录，完全关闭旧前台后复制自己的 `config/`，需要保留界面布局时一并复制 `resource/mfa_layout.json`。首次启动模板不会覆盖已有文件；旧任务清单也不会自动补入其他任务。旧版前台源码与本版不同，手动脚本更新会提示使用完整包。

## 旧版迁移

1. 关闭旧前台，保留旧目录，在新目录解压安装包。
2. 复制原来的 `config/instances/` 及 `config/config.json` 到新目录。定时任务和连接配置仍属于个人设置，迁移前自行核对。
3. 旧版文件若直接位于 `config/`，将自己的 `cards_priority.json`、`hif_drink_profiles.json`、`hif_custom_card_selection.json` 复制到新目录 `config/hif/`。
4. 在新目录执行 `.\python\python.exe tools/hif_app.py migrate`。工具先备份，再转换旧条目与图片路径，保留任务顺序、勾选、备注和适用选项；初/NIA 条目不转换。重复执行不重复迁移。
5. 若已使用独立 HIF 版本，直接保留自己的 `config/`，无需再次转换。

旧版只支持脚本更新，遇到前台、依赖或运行时变化时要求使用完整包。v261009.2 起改为上面的完整包更新流程；旧版迁移工具仍用于原合并任务与旧策略格式。

## 维护者同步上游

维护者使用 `tools/sync_upstream.py` 手动同步，不需要将上游 `main` 直接合并进 HIF 分支。GitHub 的「Sync fork」如果需要使用，只同步 `main`；HIF 分支使用下面的工具，避免覆盖本地构建工具和前台源码。

先在 `hif-independent` 分支工作，并准备已构建的固定运行环境（默认 `build/MaaGakumasu-HIF`，其他目录可用 `--runtime` 指定）。首次克隆 Fork 时若没有 `upstream` remote，执行 `git remote add upstream https://github.com/SuperWaterGod/MaaGakumasu.git`。

```powershell
# 将 v1.5.1 换成要同步的原作者版本标签，也可用 main 检查最新提交。
python tools/sync_upstream.py check --ref v1.5.1

# 使用 check 输出的完整 upstream_commit，确保应用的是刚检查的提交。
$upstreamCommit = "check 输出的完整提交号"
python tools/sync_upstream.py apply --ref $upstreamCommit --no-fetch
```

`check` 只获取指定上游、显示 `agent/` 和 `assets/` 的变更，并在暂存目录检查依赖、任务入口、HIF 节点/回调命名、图片/模型及固定 MaaFramework 加载。依赖不满足或接口不兼容时中止，不升级前台、Python 或 MaaFramework。已有上游源码修改时拒绝覆盖。

`apply` 再次检查后，只替换原版 `agent/`、`assets/` 并更新 `hif-release.json` 的 `upstream_commit`，不改日期版本号。HIF 扩展、公共模板、前台源码、全部用户配置和布局保持不变；原版目录和旧提交号备份到 `build/upstream-backups/`，替换失败自动恢复。工具不会提交、推送或发布。

成功后审查差异，更新日期版本号和新版发布说明，再执行构建、验证及实机验收后发布新的 HIF ZIP 和 SHA-256。不要移动已经发布的版本标签。构建器在本地缺少上游对象时，只从原作者仓库获取记录的固定提交，保证 GitHub 构建可重建；不会自行追踪最新版。只同步源码不会让客户端安装更新，客户端仍只认本 Fork 的 HIF 发布包，更新时保留用户配置。

## 维护者升级前台

`frontend/` 是唯一前台源码，使用本仓库的 Git 管理，不含嵌套 `.git`。当前保持 MFAAvalonia v2.14.0，前台上游与 MaaGakumasu 脚本独立同步；普通 `git pull`、`tools/sync_upstream.py` 和客户端更新都不会自动跟踪前台最新版。

有需要的修复或功能时，在临时目录取得 `hif-release.json` 记录的旧基线和目标版本，核对来源与完整提交号。将两个上游版本之间的差异以三方合并方式合入 `frontend/`，保留 HIF 定制，处理冲突；不要直接覆盖目录。完成后更新前台基线提交、版本和归档 URL/SHA-256，单独提交该次升级。不要同时升级脚本上游，除非功能需要。

验证前台编译、五个面板保存与重开、实时预览、Agent 启停、配置保护和更新流程，并在 MuMu 验证任务运行后发布。前台源码指纹写入运行包的 `hif-build-info.json`，源码不同或旧包没有指纹时要求使用完整运行包；脚本更新不会替换正在使用的前台。

整合源码后的构建应使用新运行目录；现有运行包继续保持原样。需要独立构建和验证时可指定：

```powershell
python tools/hif_build.py build --build-dir build/frontend-integration-check --output build/frontend-integration-check/runtime
python tools/hif_verify.py --runtime build/frontend-integration-check/runtime --fixture build/frontend-integration-check/verification --frontend-publish build/frontend-integration-check/frontend-publish
```

## 可重建输入

| 部件 | 固定版本 |
| --- | --- |
| 上游脚本 | v1.5.1，`3fde881ee8a87335067a76cd0ffe563ac74aa30c` |
| 前台 | v2.14.0，`16378c2a5219d7050a4b43e90629f89c146ee464` |
| MaaFramework / Python maafw | 5.12.3 |
| Python | 3.12.9，Windows x64 嵌入版 |

下载来源与 SHA-256 在 `hif-release.json`，Python 依赖版本在 `requirements-hif.txt`。定制前台源码位于 `frontend/`，包含五个面板及全部独立任务支持；构建直接编译该目录，不依赖相邻源码目录，不再下载、导出或应用前台补丁。前台基线归档的 URL 与校验值仅用于来源记录和人工升级。

安装 Git、Python 3.12.9（含 pip）与 .NET SDK 10，在具有完整 Git 历史的本仓库检出中执行：

```powershell
python tools/hif_build.py build
python tools/hif_verify.py
python tools/hif_build.py package
```

运行目录为 `build/MaaGakumasu-HIF`。构建不会覆盖已有运行目录；需要重新组装时，请先将本次生成的目录移到自己的备份位置，再构建。原版 `agent/` 与 `assets/` 保持不变，构建按固定提交导出；这两个目录被修改时拒绝打包。

## Linux x64（实验性）

在 Linux x64 上安装 Git、Python 3.12（含 pip）和 .NET SDK 10，使用完整 Git 历史执行：

```bash
python tools/hif_build.py build --platform linux-x64
python tools/hif_verify.py --runtime build/MaaGakumasu-HIF-linux-x64 --fixture build/verification-linux-x64
python tools/hif_build.py package --platform linux-x64
python tools/hif_audit.py --archive dist/MaaGakumasu-HIF-linux-x64-v261008.2.tar.gz
```

前台和验证工具需要 X11 显示环境；无桌面的构建机可使用 Xvfb。验证目录必须为新的目录。运行目录为 `build/MaaGakumasu-HIF-linux-x64`，产物为 `dist/MaaGakumasu-HIF-linux-x64-v261008.2.tar.gz` 及同名 `.sha256`。`.tar.gz` 保留可执行权限，解压到可写目录后运行 `./start.sh`。

Linux 包内置 .NET 10 与 Python 3.12.9，无需另装这两个运行时。Python 使用 Astral 的 python-build-standalone `20250317` 构建；MaaFramework 使用官方 Linux x86_64 5.12.3，下载来源和 SHA-256 固定在 `hif-release.json` 的 `linux_downloads`。系统仍需提供 X11、fontconfig、ICU 等原生依赖，ADB 设备需自行配置。当前验证环境为 Debian 13 x86_64，其他发行版与真实游戏长流程尚未验证。

组合入口兼容上游 `Shutdown.json` 导入路径的大小写差异，不修改冻结的上游文件。手动更新按当前运行包的平台选择对应压缩包与 SHA-256，拒绝跨平台安装；没有 Linux 发布资产时保留当前版本。Windows 与 Linux 完整包需分开安装。

## 发布

HIF 专用工作流只处理 Windows x64，支持手动构建与 `vYYMMDD.序号` 标签发布，例如 `v261008.1`。同一天的新构建递增序号；版本标签必须与 `hif-release.json` 相同。发布前运行完整本地检查，推送和远程发布需仓库拥有者明确确认。

Linux 专用工作流 `.github/workflows/hif-linux-release.yml` 在 Ubuntu 24.04 构建、使用 Xvfb 完整验证并审计运行包，随后向配置版本的已有 Release 添加 Linux 压缩包、校验文件和说明，不替换 Windows 附件。手动运行默认仅生成验证产物，勾选 `publish` 才发布；在 `hif-independent` 推送该工作流文件的改动也会触发发布，维护者提交前需确认发布意图。Release 中的 Linux 源码链接指向实际构建提交，原 Windows 标签保持原样。
