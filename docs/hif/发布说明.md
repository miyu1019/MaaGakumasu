# MaaGakumasu-HIF v261010.2

## v261010.2 更新内容

- 饮料详情连续两次取消未成功时观察 10 秒，已退出则直接继续；仍是同一详情时重新识别取消按钮并最后重试一次。不会重复使用或舍弃饮料。
- 训练点击前复核日期与三个公开课程按钮，过渡画面不再强制点击；已到非训练日时释放训练门控，避免挡住第 6 天休息。
- 饮料所持上限页提交后支持 SP 课程额外饮料奖励横幅；CONNECTING 时先等待连接恢复，最多 30 秒，不重复提交上一页。
- 手动停止按取消处理，不再误报饮料详情关闭失败。

下面保留 v261010.1 的完整内容与升级说明。

本版更新 HIF 饮料所持上限处理、技能卡定制确认和职业配置分享。使用 Windows x64 完整包升级，保留个人设置。

## v261010.1 更新内容

- 修复勾选式饮料所持上限页的基础补选：保留已有选择，先补手持，缺位时继续补收到的饮料；支持滚动查找隐藏候选和同款多瓶。
- 新增任务开关「所持上限页按优先级保留」，默认关闭，位于「相谈购买饮料」之前。开启后按当前职业的启用名单、名单外、禁用项顺序保留，同级优先手持；实际容量由清单与剩余选择数核对。普通领取页的舍弃逻辑保持独立。
- 扫描使用实际滚动位移关联条目，点击逐瓶核对勾选与计数；信息详情读取图标右侧名称，确认关闭后继续。优先级识别失败时恢复已有选择并转基础补选。
- 「残す」未生效时重新检查当前页后有限补点；连续出现下一上限页时重新处理，不能区分时也重新扫描。成功领取后点击左上角跳过动画，并容忍饮料图标被 OCR 合并到完整名称前的短前缀。普通领取页优先识别领取提示和按钮，避免瓶身名称被误判为动画。
- 技能卡定制等待明确执行结果，避免动画中重复提交；提交前只剩一次、当前卡成功提示连续确认后，正确记录整卡完成，解决上限标签消失后误报未完成。中场入口确认、卡名读取和定制项目选择同步修正。
- 增加按职业导入、导出战斗出牌优先级及相关规则，以 JSON 文件分享。优先获取和换出名单不随文件导出，导入时保留原名单；检查后点击保存生效。职业不匹配或规则无效时提示原因并保留已有配置。
- 新实例默认关闭实时画面；保留已有实例偏好。同步已合并的相谈更新，在商店等待期间点击左上角推进演出。

最新一轮 MuMu 育成正常完成；饮料上限补选、领取动画退出，以及三张已执行定制的卡正确记录完成，均通过实机日志验证。普通领取页瓶身名称误判另以实机截图原生 OCR 重放及回归验证。323 项 Python 测试通过（1 项跳过），完整包通过原生前台保存重开、更新回滚及公开配置审计；不代表全部职业和组合均完成实机覆盖。

## 升级提示

使用 Windows x64 完整包升级。支持完整包更新的版本可在 Maa 内更新；手动更换目录时，先导出设置，再在新版导入，保留个人职业策略、实例、连接和窗口布局。
